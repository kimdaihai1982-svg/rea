01
Bắt đầu bằng giao diệnĐăng nhập dashboard một lần, thao tác file và tạo database bằng nút
  1. Mở domain HTTPS đã cấu hình (maychu247.uk), qua Access và đăng nhập dashboard.
  2. Chọn Tập tin để mở thư mục, upload, tạo file, sửa và tải xuống ngay tại đây.
  3. Chọn Cơ sở dữ liệu để tạo database có tên mới, xem danh sách hoặc mở SQL Admin khi cần quản lý bảng.
  4. Chọn Website & Domain để tạo cấu hình website riêng; đọc đúng giới hạn khởi động/domain trước khi xác nhận.
  5. Chọn Giám sát nội bộ hoặc Sao lưu để xem số liệu và chạy backup thật.

Tab Tập tin và nút tạo database dùng phiên đăng nhập dashboard, không yêu cầu lệnh SSH. SQL Admin vẫn là công cụ riêng với tài khoản database; không có SSO tự động hoặc trình soạn SQL mới.

SSH chỉ dành cho bảo trì/cứu hộ và những chức năng chưa được tích hợp. Không coi mọi chức năng đã hoàn tất nếu giao diện ghi rõ chưa hỗ trợ.

Không gửi ảnh có mật khẩu/token lên chat. Giữ tài khoản quản trị riêng và chỉ cấp cho người tin cậy.

02
Quản lý file bằng nút bấmKhông cần lệnh SSH, mật khẩu File Browser hoặc cổng 18082
  1. Chọn tab Tập tin. Danh sách là thư mục/file thật trong projects/.
  2. Bấm tên thư mục để mở. Dùng Projects, Thư mục cha hoặc breadcrumb để quay lại.
  3. Vào demo → public để chỉnh website chính đang chạy.
  4. Bấm Tải file lên để chọn file từ PC (tối đa 1 MiB). Tên trùng bị từ chối, không tự ghi đè.
  5. Bấm File văn bản để tạo hello.php, index.html hoặc mã nguồn mới.
  6. Bấm một file UTF-8, sửa nội dung, rồi Lưu thay đổi thật. File lớn/nhị phân chỉ tải xuống, không soạn.
  7. Bấm Thư mục để tạo thư mục bên trong nơi đang mở.

Không hiện “online” hay “đã lưu” giả: khi API lỗi phải báo lỗi. Đừng tải .env hoặc secret vào public root; không soạn cùng file bằng công cụ khác khi đang lưu.

Giới hạn hiện tại: chỉ projects/ của stack chính; sites/ riêng, giải nén, xóa, đổi tên và phục hồi lịch sử chưa có GUI. Không cần chạy File Browser cũ cho luồng này.
03
Đưa website PHP đầu tiên lênThử file an toàn trước khi import dự án lớn

Muốn tạo thư mục mới: tab Tập tin → Tạo thư mục web → nhập tên → xác nhận. Nó hiện trong File Browser, nhưng chưa tự thành website có domain.

  1. Trong tab Tập tin, mở demo → public.
  2. Tạo file hello.php, nhập nội dung dưới rồi lưu.
  3. Mở http://localhost:18080/hello.php trên PC.
  4. Thấy “Xin chào từ MayChu247” nghĩa file PHP đã được thực thi.
<?php
header('Content-Type: text/plain; charset=utf-8');
echo 'Xin chào từ MayChu247';

Không dùng phpinfo() trên website public vì có thể lộ môi trường. Với Laravel/framework: chỉ đặt public root ở thư mục public; private code, .env và vendor config không được public. Thư mục uploads/cache cần cấu hình writable riêng; đừng chmod 777 cả dự án.

Tạo cấu hình website riêng bằng nút Tạo website mới ở tab Website & Domain; khởi động và gắn domain tiếp theo MULTISITE.md.

Muốn tạo database tên mới: mở tab Cơ sở dữ liệu → Tạo database SQL. Sau khi tạo, đổi ô Database trong Adminer sang tên vừa tạo, giữ user appuser.

Password lấy từ DB_PASSWORD của stack mới. Trên SSH Ubuntu, lệnh dưới sẽ hiển thị mật khẩu; chỉ xem riêng và lưu trong password manager:

sudo sed -n 's/^DB_PASSWORD=//p' /opt/maychu247-v2/.env

Chọn Vietnamese ở Language nếu phiên bản hỗ trợ. Sau đăng nhập:

  • Create table / Tạo bảng: tạo bảng cho dự án trong appdb.
  • Import: chọn file SQL và kiểm tra database đích trước khi thực thi.
  • Export: chọn SQL để xuất cấu trúc/dữ liệu. Đây không thay thế backup toàn hệ thống.
  • SQL command: chạy SELECT để xem dữ liệu; tránh DROP/DELETE/UPDATE nếu chưa backup.
appuser chỉ quản lý appdb, không có quyền tạo mọi database/user. Site riêng dùng DB instance/secret riêng, không đăng nhập bằng thông tin stack chính.
05
Giám sát do MayChu247 tự thiết kếKhông cần Kuma hoặc tài khoản giám sát thứ hai

Chọn tab Giám sát nội bộ. Sau khi UI khởi động, bộ kiểm tra lấy mẫu lần đầu rồi lặp lại mỗi 30 giây. Up chỉ nói phép thử đã đạt, không phải chứng nhận an toàn.

  • PHP: kiểm tra HTTP 200 tại loopback cổng 18080. Trang mẫu có kiểm tra DB; app thay thế phải tự có health endpoint phù hợp.
  • MQTT: TCP 1884 mở; chưa kiểm tra password, ACL, publish/subscribe hoặc ghi SQL.
  • SQL Admin / File Manager: kiểm tra TCP mở, không xác minh tài khoản hoặc dữ liệu.

Ví dụ container dùng tên nội bộ http://web:8080/, Hostname db · Port 3306, Hostname mqtt · Port 1883; bộ giám sát host hiện chỉ dùng các cổng loopback cố định đã publish, không kết nối DB trực tiếp.

Sự kiện tối đa 100 dòng trong RAM, mất khi restart UI. Chưa có email/Telegram/SMS, lưu lịch sử dài hạn hoặc theo dõi từ ngoài máy. Máy mất điện/mạng thì bộ giám sát cùng máy cũng ngừng hoạt động.

Thử nghiệm khi chưa có dữ liệu quan trọng: dừng web ở tab Dịch vụ, đợi monitor báo Down; chạy lại web và kiểm tra Up. Backup gây gián đoạn cũng có thể tạo sự kiện Down.

06
Kết nối MQTTDùng client MQTT Explorer qua SSH tunnel

Trên PC mở thêm tunnel (giữ cửa sổ này hoạt động):

ssh -L 1884:127.0.0.1:1884 kimdaihai@192.168.1.11

MQTT Explorer: host 127.0.0.1, port 1884, username mqttuser; password đọc riêng trên SSH Ubuntu:

sudo sed -n 's/^MQTT_PASSWORD=//p' /opt/maychu247-v2/.env

Subscribe/publish thử topic home/sensor/data với payload:

{"device_id":"ESP32_01","temp":30.5,"hum":70}

Pub/sub thành công chưa có nghĩa dữ liệu được ghi SQL: worker MQTT→SQL chưa kèm trong bộ mẫu. Không mở cổng MQTT TCP ra WAN. Thiết bị không tin cậy cần user/ACL topic riêng.

07
Sao lưu và kiểm tra khôi phụcBackup thật có thể gián đoạn dịch vụ ngắn

Trong tab Sao lưu → Chạy backup thật → đọc xác nhận. Theo dõi job ở Tổng quan, sau đó kiểm tra snapshot. COMPLETE chỉ là dấu script hoàn tất, không chứng minh restore thành công.

Bật lịch hằng ngày trên SSH sau khi backup thủ công thành công:

sudo bash /opt/maychu247-v2/scripts/install-backup-timer.sh

Nếu timer đã tồn tại, không ghi đè; kiểm tra:

sudo systemctl list-timers maychu247-backup.timer
sudo systemctl cat maychu247-backup.service
sudo journalctl -u maychu247-backup.service -n 50 --no-pager

ExecStart nên gọi backup-all.sh để bao gồm các site. Giữ 14 ngày cục bộ; cần bản mã hóa offsite riêng. Thử restore trên VM khác theo README/MULTISITE.md, không phục hồi đè production chỉ để “test”.

Ranh giới quản trị

  • Web chạy bằng user riêng, không có Docker socket hoặc quyền sudo.
  • Agent cục bộ chỉ cho phép lệnh dịch vụ cố định, backup và tạo cấu hình site qua bộ tạo đã kiểm tra đầu vào.
  • Phiên 1 giờ, cookie HttpOnly / SameSite, kiểm tra Origin và CSRF cho thao tác ghi.
  • Chỉ nghe 127.0.0.1:18000; SSH tunnel mặc định, public domain tùy chọn qua connector riêng và Access.
